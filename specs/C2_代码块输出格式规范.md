# C2 代码块输出格式规范

## 1. 总则

### 1.1 目标
定义管线中LLM输出的代码块格式标准——从声明语法、解析规则到多语言格式差异，确保代码生成结果可被确定性地提取、校验和写入文件，为 P2（输出约束声明）、P4（分段衔接格式）提供格式基础。

### 1.2 定位

| 维度 | 说明 |
|------|------|
| **与P2的关系** | P2定义Prompt层面的输出格式约束声明（````{language}:{filepath}```语法声明）；C2定义该声明背后的**完整输出格式规范**——文件头、类排序、方法排序、多文件输出等细节规则 |
| **与P4的关系** | P4定义跨代码块的衔接格式约定（import声明衔接、类继承衔接）；C2定义单个代码块内部的格式标准，P4在C2基础上叠加衔接信息 |
| **与C1的关系** | C1定义目录结构；C2代码块中的文件路径必须与C1目录对齐 |
| **与C3的关系** | C3定义命名规范；C2输出的标识符命名必须符合C3规则 |

### 1.3 设计原则

| 原则 | 说明 |
|------|------|
| **格式先行** | 输出格式是代码可解析的前提，格式错误=生成失败，优先级最高 |
| **路径即位置** | 代码块声明的文件路径决定写入位置，路径必须精确、完整、与C1对齐 |
| **语言差异化** | 不同语言有不同的惯用格式，Python/Vue/SQL/YAML各有专属格式规则 |
| **解析确定性** | 任何符合C2格式的输出，必须能被P2的`extract_code_blocks()`无歧义解析 |
| **单文件粒度** | 每个代码块对应一个文件，一个LLM调用最多输出一个代码块（DevOps Agent除外） |

## 2. 代码块声明语法

### 2.1 基本格式

LLM输出的代码块使用以下格式声明：

```
```{language}:{filepath}
{code content}
```
```

**语法规则**：

| 元素 | 格式 | 说明 |
|------|------|------|
| language | 小写语言标识 | `python`、`vue`、`javascript`、`sql`、`json`、`yaml`、`dockerfile`、`bash` |
| filepath | 相对于项目根的路径 | 与C1目录对齐，如`app/services/user.py`、`src/views/user/UserView.vue` |
| 代码内容 | 语言对应的合法代码 | 严格遵循语言语法和C系列规范 |

### 2.2 语言标识映射

| 后端文件 | language标识 | 前端/DevOps文件 | language标识 |
|---------|-------------|----------------|-------------|
| `*.py` | `python` | `*.vue` | `vue` |
| `*.sql` | `sql` | `*.js` | `javascript` |
| — | — | `*.json` | `json` |
| — | — | `*.yml` / `*.yaml` | `yaml` |
| — | — | `Dockerfile` | `dockerfile` |
| — | — | `*.sh` | `bash` |
| — | — | `*.conf` | `nginx` |
| — | — | `*.scss` / `*.css` | `css` |

### 2.3 文件路径规则

| 规则 | 说明 | 示例 |
|------|------|------|
| **相对路径** | 相对于`artifacts/backend/`或`artifacts/frontend/` | `app/services/user.py` |
| **无前导`/`** | 不以`/`开头 | ✅ `app/models/user.py` ❌ `/app/models/user.py` |
| **与C1对齐** | 路径必须在C1目录树中存在对应位置 | 不可出现C1未定义的路径层级 |
| **模块归属** | 路径隐含模块归属（A1生成顺序） | `app/services/user.py` → user_management模块 |

### 2.4 DevOps多文件输出

DevOps Agent单次调用可输出多个文件，使用序号标记：

```
[1/7] docker/backend.Dockerfile
```dockerfile:docker/backend.Dockerfile
FROM python:3.11-slim
...
```

[2/7] docker/frontend.Dockerfile
```dockerfile:docker/frontend.Dockerfile
FROM node:20-alpine
...
```
```

序号格式：`[{当前序号}/{总数}] {文件描述}`

## 3. Python文件输出格式

### 3.1 文件结构模板

Python文件按以下顺序组织：

```
"""模块文档字符串（Google风格）。"""

# 1. 标准库导入
import os
import json

# 2. 第三方库导入
from flask import Blueprint, request
from sqlalchemy import desc

# 3. 本地导入
from app.models.user import User, Role
from app.api.user_interface import IUserManager
from app.utils.exceptions import ServiceException

# 4. 模块级常量
DEFAULT_PAGE_SIZE = 20

# 5. 模块级变量（Blueprint、logger等）
user_bp = Blueprint('user', __name__, url_prefix='/api/v1/users')
logger = __import__('logging').getLogger(__name__)

# 6. 类定义（按ABC→具体类排序）
class UserManager(IUserManager):
    """用户管理服务。"""

    def list_users(self, page: int = 1, size: int = DEFAULT_PAGE_SIZE) -> dict:
        """获取用户列表。

        Args:
            page: 页码，从1开始。
            size: 每页数量。

        Returns:
            分页结果字典。

        Raises:
            ServiceException: 当查询参数无效时。
        """
        ...

# 7. 路由函数（仅Router文件）
@user_bp.route('/', methods=['GET'])
@audit_log(action="list_users")
def list_users():
    """用户列表接口。"""
    ...
```

### 3.2 文件头规范

| 元素 | 要求 | 说明 |
|------|------|------|
| 模块文档字符串 | 必须，Google风格 | 描述模块用途，1-2行 |
| 编码声明 | 不需要 | Python3默认UTF-8 |
| Shebang | 不需要 | 由Dockerfile指定 |

### 3.3 类排序规则

同一文件内多个类的排序：

1. ABC抽象基类在前
2. 具体实现类在后
3. 同类按模块生成顺序排列

```python
# app/models/user.py
class Role(db.Model, BaseModel):
    """角色模型。"""
    ...

class User(db.Model, BaseModel):
    """用户模型。"""
    ...
```

### 3.4 方法排序规则

类内方法排序：

| 顺序 | 方法类型 | 说明 |
|------|---------|------|
| 1 | `__init__` | 构造函数 |
| 2 | ABC抽象方法实现 | 与ABC声明顺序一致 |
| 3 | 公有方法 | 按业务逻辑重要性排序 |
| 4 | 私有方法 | `_`前缀，按调用顺序排序 |
| 5 | 静态/类方法 | `@staticmethod`/`@classmethod` |

### 3.5 特殊文件格式

#### `app/__init__.py` — 应用工厂

```python
"""Flask应用工厂模块。"""

from flask import Flask
from app.extensions import db, socketio, jwt
from app.config import config


def create_app(config_name='default'):
    """创建Flask应用实例。

    Args:
        config_name: 配置环境名称。

    Returns:
        Flask应用实例。
    """
    app = Flask(__name__)
    app.config.from_object(config[config_name])

    # 初始化扩展
    db.init_app(app)
    socketio.init_app(app)
    jwt.init_app(app)

    # 注册Blueprint
    from app.api import register_blueprints
    register_blueprints(app)

    return app
```

#### `app/api/__init__.py` — Blueprint注册

```python
"""API Blueprint注册模块。"""

from flask import Flask


def register_blueprints(app: Flask) -> None:
    """注册所有API Blueprint。

    Args:
        app: Flask应用实例。
    """
    from app.api.user import user_bp
    from app.api.alert import alert_bp
    from app.api.log import log_bp
    from app.api.monitor import monitor_bp
    from app.api.network import network_bp

    app.register_blueprint(user_bp)
    app.register_blueprint(alert_bp)
    app.register_blueprint(log_bp)
    app.register_blueprint(monitor_bp)
    app.register_blueprint(network_bp)
```

#### `run.py` — 启动入口

```python
"""应用启动入口。"""

from app import create_app
from app.extensions import socketio

app = create_app()

if __name__ == '__main__':
    socketio.run(app, host='0.0.0.0', port=5000, debug=True)
```

## 4. Vue文件输出格式

### 4.1 文件结构模板

Vue单文件组件（SFC）按以下顺序组织：

```vue
<template>
  <!-- 模板内容 -->
</template>

<script setup>
// 1. Vue核心导入
import { ref, reactive, computed, onMounted, onUnmounted } from 'vue'

// 2. 第三方库导入
import { ElMessage, ElMessageBox } from 'element-plus'
import * as echarts from 'echarts'

// 3. 本地导入
import { getUserList, createUser } from '@/api/user'
import { useUserStore } from '@/stores/user'
import StatusTag from '@/components/business/StatusTag.vue'

// 4. 组合式函数调用
const userStore = useUserStore()
const router = useRouter()

// 5. 响应式状态
const loading = ref(false)
const userList = ref([])
const pagination = reactive({ page: 1, size: 20, total: 0 })

// 6. 计算属性
const filteredList = computed(() => ...)

// 7. 方法
const fetchUsers = async () => { ... }
const handleCreate = () => { ... }

// 8. 生命周期
onMounted(() => { fetchUsers() })
onUnmounted(() => { ... })
</script>

<style scoped lang="scss">
/* 组件样式 */
</style>
```

### 4.2 三段顺序规则

Vue SFC的三段固定顺序：`<template>` → `<script setup>` → `<style scoped>`

| 段落 | 必须 | 说明 |
|------|------|------|
| `<template>` | 是 | HTML模板，使用Element Plus组件 |
| `<script setup>` | 是 | 组合式API，禁止Options API |
| `<style scoped>` | 否 | 局部样式，使用`scoped`和`lang="scss"` |

### 4.3 script内部排序规则

| 顺序 | 内容 | 说明 |
|------|------|------|
| 1 | Vue核心导入 | `ref`, `reactive`, `computed`, `onMounted` 等 |
| 2 | 第三方库导入 | Element Plus, ECharts, Socket.IO |
| 3 | 本地导入 | API函数, Store, 子组件 |
| 4 | 组合式函数调用 | `useUserStore()`, `useRouter()` |
| 5 | 响应式状态声明 | `ref()`, `reactive()` |
| 6 | 计算属性 | `computed()` |
| 7 | 方法定义 | 普通函数和`async`函数 |
| 8 | 生命周期钩子 | `onMounted`, `onUnmounted` |

### 4.4 组件命名规则

- 组件文件名：PascalCase（如`UserTable.vue`、`StatusTag.vue`）
- 模板中引用：kebab-case（如`<user-table />`、`<status-tag />`）
- 组件注册：`<script setup>`中直接import即可使用，无需显式注册

## 5. JavaScript文件输出格式

### 5.1 API调用文件

```javascript
/**
 * 用户管理API模块。
 */
import request from '@/api'

/**
 * 获取用户列表。
 * @param {Object} params - 查询参数
 * @param {number} params.page - 页码
 * @param {number} params.size - 每页数量
 * @returns {Promise<Object>} 分页结果
 */
export function getUserList(params) {
  return request({ url: '/api/v1/users', method: 'get', params })
}

/**
 * 创建用户。
 * @param {Object} data - 用户数据
 * @returns {Promise<Object>} 创建结果
 */
export function createUser(data) {
  return request({ url: '/api/v1/users', method: 'post', data })
}
```

**格式规则**：

| 规则 | 说明 |
|------|------|
| JSDoc注释 | 每个导出函数必须有JSDoc |
| 导出方式 | `export function`（命名导出），禁止`export default` |
| 函数命名 | camelCase |
| URL路径 | 必须与api_def.json一致 |

### 5.2 Pinia Store文件

```javascript
/**
 * 用户状态管理模块。
 */
import { defineStore } from 'pinia'
import { getUserList } from '@/api/user'

export const useUserStore = defineStore('user', {
  state: () => ({
    userList: [],
    currentUser: null,
    loading: false
  }),

  getters: {
    userCount: (state) => state.userList.length
  },

  actions: {
    async fetchUsers(params) {
      this.loading = true
      try {
        const res = await getUserList(params)
        this.userList = res.data.items
      } catch (error) {
        ElMessage.error(error.message || '获取用户列表失败')
      } finally {
        this.loading = false
      }
    }
  }
})
```

**格式规则**：

| 规则 | 说明 |
|------|------|
| 命名 | `use`前缀 + PascalCase功能名 |

## 6. SQL文件输出格式

### 6.1 建库SQL

```sql
-- ============================================================
-- 网络安全设备后台管理系统 - 数据库初始化脚本
-- 生成时间: 2026-04-30
-- 数据库: MySQL 8.0
-- 字符集: utf8mb4
-- ============================================================

-- -----------------------------------------------------------
-- 用户与角色
-- -----------------------------------------------------------

CREATE TABLE IF NOT EXISTS `role` (
    `id` INT AUTO_INCREMENT PRIMARY KEY,
    `name` VARCHAR(50) NOT NULL COMMENT '角色名称',
    `description` VARCHAR(200) DEFAULT NULL COMMENT '角色描述',
    `created_at` DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP,
    `updated_at` DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP,
    UNIQUE KEY `uk_role_name` (`name`)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COLLATE=utf8mb4_unicode_ci COMMENT='角色表';

-- -----------------------------------------------------------
-- 告警
-- -----------------------------------------------------------

CREATE TABLE IF NOT EXISTS `alert` (
    ...
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COLLATE=utf8mb4_unicode_ci COMMENT='告警表';
```

**格式规则**：

| 规则 | 说明 |
|------|------|
| 文件头注释 | 项目名 + 生成时间 + 数据库类型 + 字符集 |
| 表注释 | `COMMENT`子句 |
| 列注释 | `COMMENT`子句 |
| 分段注释 | `--` + 分隔线 + 模块名 |
| IF NOT EXISTS | 建表语句必须带，支持幂等执行 |
| 字符集 | `utf8mb4` + `utf8mb4_unicode_ci` |

## 9. 边界情况处理

### 9.1 代码块嵌套

当代码内容本身包含三反引号时，使用四反引号声明：

```
````python:app/utils/markdown.py
def render_markdown(text):
    """渲染Markdown文本，包含代码块。"""
    # 处理 ```python 这样的嵌套
    return text.replace("```", "\\`\\`\\`")
````
```

规则：声明用的反引号数量必须比内容中最大反引号数量多1。

### 9.2 空文件

空`__init__.py`输出格式：

```python:app/models/__init__.py
```

（只有声明行，无代码内容）

### 9.3 截断续写

当输出被截断时（P4 §5），续写代码块仍需完整声明：

```
```python:app/services/user.py
# ... 续写内容
```
```

P2的`extract_code_blocks()`将自动与前置内容拼接。

### 9.4 修复输出

修复模板（fix_）的输出格式与生成模板相同，但允许只输出修改部分：

```
```python:app/services/user.py
# [FIX] 修复分页查询的off-by-one错误
def list_users(self, page: int = 1, size: int = DEFAULT_PAGE_SIZE) -> dict:
    offset = (page - 1) * size  # 修复：原来是 page * size
    ...
```
```

修复标记 `[FIX]` 为可选注释，帮助人工审查定位修改点。

## 10. 格式校验规则

### 10.1 P2解析校验

P2的`extract_code_blocks()`对C2格式的校验：

| 校验项 | 规则 | 失败处理 |
|--------|------|---------|
| 声明存在性 | 必须有`{language}:{filepath}`声明 | L1格式错误 |
| language合法性 | 必须在2.2映射表中 | L1格式错误 |
| filepath合法性 | 必须符合2.3路径规则 | L1格式错误 |
| 代码非空 | 非空`__init__.py`外不可为空 | L1格式错误 |
| 闭合标记 | 代码块必须有闭合` ``` ` | L1格式错误，尝试自动闭合 |

### 10.2 Validate Agent格式校验

| 校验项 | 规则 | 检查层级 |
|--------|------|---------|
| Python文件头 | 必须有模块文档字符串 | L2 LLM审查 |
| Vue三段顺序 | template→script→style | L1静态分析 |
| 导入分组 | 三组分隔（标准→第三方→本地） | L1静态分析（ast/ruff） |
| JSDoc | API/Store/Composable导出函数必须有JSDoc | L2 LLM审查 |

## 11. 与其他规范的联动

### 11.1 与P2的联动

| C2定义 | P2消费方式 |
|--------|----------|
| 代码块声明语法 | P2 §4 OutputParser的`extract_code_blocks()`解析此语法 |
| 格式校验规则 | P2 §5 L1格式校验执行C2定义的格式校验项 |
| DevOps多文件输出 | P2 §4.3多文件解析策略处理序号标记 |

### 11.2 与P4的联动

| C2定义 | P4消费方式 |
|--------|----------|
| Python文件结构模板 | P4衔接约束中的导入声明格式基于C2模板 |
| Vue script排序 | P4前端衔接约束中的导入衔接基于C2排序规则 |
| 修复输出格式 | P4 §6修复循环衔接使用C2修复标记格式 |

### 11.3 与C1的联动

| C2定义 | C1消费方式 |
|--------|----------|
| 文件路径 | C1 project_structure枚举所有C2声明的文件路径 |
| 模块归属 | C2路径隐含的模块归属与C1模块定义一致 |
