# C3 命名规范

## 1. 总则

### 1.1 目标
定义管线生成代码中的命名规则——涵盖Python、Vue/JavaScript、SQL、JSON、API等各语言的标识符命名约定，确保代码命名一致、可读、可跨语言映射，为 C4（代码风格）、C5（导入规范）、C6（错误处理）提供命名基础。

### 1.2 定位

| 维度 | 说明 |
|------|------|
| **与D1的关系** | D1 §11.1定义了JSON字段的snake_case命名规则；C3将此规则扩展到代码标识符，并增加跨语言映射规则 |
| **与P4的关系** | P4 §10定义7维风格样本提取，其中"命名风格"维度的规则来源于C3 |
| **与C1的关系** | C1定义目录和文件命名；C3定义目录内代码标识符的命名 |
| **与C5的关系** | C5定义导入路径规范；导入路径中的模块名、函数名、类名必须符合C3命名 |
| **与C6的关系** | C6定义异常类命名（如`ServiceException`）；C3定义异常类命名的一般规则 |

### 1.3 设计原则

| 原则 | 说明 |
|------|------|
| **语言惯用** | 遵循各语言的PEP8/官方风格指南惯例，不自创风格 |
| **跨语言映射** | 同一概念在不同语言间有确定的命名映射规则（如snake_case↔camelCase） |
| **业务语义优先** | 命名表达业务含义，不用技术缩写，不用无意义前缀 |
| **db_model为准** | 前后端字段命名冲突时，以db_model.json的snake_case为权威（A4 §5.2） |
| **可枚举可校验** | 命名规则可由正则表达式或AST检查工具校验 |

## 2. Python命名规则

### 2.1 总览

| 标识符类型 | 命名风格 | 示例 |
|-----------|---------|------|
| 模块名 | snake_case | `user.py`, `alert_interface.py` |
| 包名 | snake_case | `api/`, `services/`, `models/` |
| 类名 | PascalCase | `UserManager`, `IUserManager`, `ServiceException` |
| 函数/方法名 | snake_case | `list_users`, `create_alert` |
| 变量名 | snake_case | `user_list`, `alert_count` |
| 常量 | UPPER_SNAKE_CASE | `DEFAULT_PAGE_SIZE`, `MAX_RETRY_COUNT` |
| 装饰器 | snake_case | `@audit_log`, `@require_role` |
| 异常类 | PascalCase + `Error`/`Exception` 后缀 | `ServiceException`, `ValidationError` |
| ABC接口 | PascalCase + `I` 前缀 | `IUserManager`, `IAlertManager` |
| Blueprint | snake_case + `_bp` 后缀 | `user_bp`, `alert_bp` |
| 私有方法 | `_` 前缀 + snake_case | `_validate_input`, `_build_query` |
| 类型变量 | PascalCase | `T`, `TModel` |

### 2.2 类命名详细规则

#### ABC接口类

```
命名模式: I{ModuleName}Manager
```

| 接口类 | 命名 | 说明 |
|--------|------|------|
| 用户管理 | `IUserManager` | `I`前缀 + 业务域 + `Manager`后缀 |
| 告警管理 | `IAlertManager` | 同上 |
| 日志管理 | `ILogManager` | 同上 |
| 系统监控 | `IMonitorManager` | 同上 |
| 网络状态监控 | `INetworkManager` | 同上 |
| 设备策略 | `DeviceStrategy` | 无`I`前缀，`Strategy`后缀 |

#### 实现类

```
命名模式: {ModuleName}Manager / {ModuleName}Strategy
```

| 实现类 | 命名 | 继承 |
|--------|------|------|
| 用户管理 | `UserManager` | `IUserManager` |
| 告警管理 | `AlertManager` | `IAlertManager` |
| 防火墙策略 | `FirewallStrategy` | `DeviceStrategy` |
| IDS策略 | `IDSStrategy` | `DeviceStrategy` |

#### 数据模型类

```
命名模式: PascalCase，与数据库表名对应
```

| 模型类 | 数据库表 | 说明 |
|--------|---------|------|
| `User` | `user` | 单数形式 |
| `Role` | `role` | 单数形式 |
| `Alert` | `alert` | 单数形式 |
| `AlertRule` | `alert_rule` | 多词snake_case |

| `NetworkStatus` | `network_status` | 多词snake_case |

### 2.3 函数/方法命名详细规则

#### CRUD操作命名

|------|---------|------|

| 类型 | 命名模式 | 示例 |

| 装饰器 | 命名 | 用途 |

## 5. JSON字段命名规则

### 5.1 通用规则

与D1 §11.1一致：

| 规则 | 说明 | 示例 |
|------|------|------|
| snake_case | 所有JSON字段使用snake_case | `user_id`, `created_at` |
| 无缩写 | 不使用非通用缩写 | ✅ `description` ❌ `desc` |
| 布尔前缀 | `is_` / `has_` / `should_` | `is_active`, `has_permission` |
| 时间后缀 | `_at` | `created_at`, `updated_at` |
| 计数后缀 | `_count` | `total_count`, `error_count` |
| ID后缀 | `_id` | `user_id`, `pipeline_id` |

### 5.2 API响应JSON

统一响应格式（A1决策摘要）：

```json
{
  "code": 200,
  "data": { ... },
  "message": "success"
}
```

分页响应：

```json
{
  "code": 200,
  "data": {
    "items": [...],
    "total": 100,
    "page": 1,
    "size": 20
  },
  "message": "success"
}
```

## 7. 跨语言命名映射

### 7.1 映射规则

同一业务概念在不同语言间的命名映射：

| 概念 | Python (snake_case) | Vue/JS (camelCase) | SQL (snake_case) | JSON (snake_case) |
|------|--------------------|--------------------|------------------|-------------------|
| 用户ID | `user_id` | `userId` | `user_id` | `user_id` |
| 创建时间 | `created_at` | `createdAt` | `created_at` | `created_at` |
| 告警级别 | `alert_level` | `alertLevel` | `alert_level` | `alert_level` |
| 是否激活 | `is_active` | `isActive` | `is_active` | `is_active` |

### 7.2 映射函数

```python
# Python端：snake_case → camelCase
def to_camel_case(snake_str: str) -> str:
    """将snake_case转换为camelCase。"""
    components = snake_str.split('_')
    return components[0] + ''.join(x.title() for x in components[1:])

# 示例
# to_camel_case('user_id') → 'userId'
# to_camel_case('created_at') → 'createdAt'
```

```javascript
// Vue/JS端：camelCase → snake_case
function toSnakeCase(camelStr) {
  return camelStr.replace(/[A-Z]/g, letter => `_${letter.toLowerCase()}`)
}

// 示例
// toSnakeCase('userId') → 'user_id'
// toSnakeCase('createdAt') → 'created_at'
```

### 7.3 权威来源规则

A4 §5.2定义：**当后端snake_case字段与前端camelCase字段命名冲突时，以db_model.json为准**。

- db_model.json使用snake_case（与SQL一致）
- Python代码直接使用db_model.json的snake_case
- Vue/JS代码在显示层使用camelCase，API请求/响应层使用snake_case
- 前端API模块负责snake_case ↔ camelCase的转换（axios拦截器）

## 9. 命名校验规则

### 9.1 Python命名校验

由Validate Agent Layer1（ruff + ast）执行：

| 校验项 | 正则/规则 | 错误级别 |
|--------|----------|---------|
| 类名PascalCase | `^[A-Z][a-zA-Z0-9]*$` | Error |
| 函数名snake_case | `^[a-z][a-z0-9_]*$` | Error |
| 常量UPPER_SNAKE | `^[A-Z][A-Z0-9_]*$`（模块级） | Warning |
| ABC前缀I | ABC类必须`I`前缀 | Error |
| Blueprint后缀_bp | Blueprint变量必须`_bp`后缀 | Error |

### 9.2 Vue/JS命名校验

| 校验项 | 正则/规则 | 错误级别 |
|--------|----------|---------|
| 组件文件名PascalCase | `^[A-Z][a-zA-Z0-9]*\.vue$` | Error |
| API函数camelCase | `^[a-z][a-zA-Z0-9]*$` | Error |
| Store命名use*Store | `^use[A-Z][a-zA-Z0-9]*Store$` | Error |
| Composable命名use* | `^use[A-Z][a-zA-Z0-9]*$` | Error |

### 9.3 跨语言一致性校验

Validate Agent Layer2.5契约校验中的命名一致性：

| 校验项 | 规则 | 检查层级 |
|--------|------|---------|
| API路径一致 | 前端API调用路径与api_def.json一致 | L2.5 |
| 字段名映射 | 前端camelCase与后端snake_case有确定映射关系 | L2.5 |
| 表名与模型名对应 | SQL表名→Python模型类名可映射 | L2 |

## 10. 与其他规范的联动

### 10.1 与P4的联动

| C3定义 | P4消费方式 |
|--------|----------|
| Python类命名规则 | P4 §3签名级衔接提取类名，需符合C3 PascalCase规则 |
| Vue组件命名规则 | P4前端衔接提取组件注册名，需符合C3 PascalCase规则 |
| 命名风格维度 | P4 §10风格样本提取"命名风格"维度，规则来源为C3 |

### 10.2 与C1的联动

| C3定义 | C1消费方式 |
|--------|----------|
| 文件命名规则 | C1目录树中的文件名必须符合C3文件命名规则 |
| 模块命名规则 | C1 project_structure的模块key必须符合C3模块命名 |

### 10.3 与D1的联动

| C3定义 | D1消费方式 |
|--------|----------|
| JSON字段命名 | D1 Schema字段名遵循C3 snake_case规则 |
| _at/_count后缀 | D1通用元数据字段与C3命名后缀规则一致 |
