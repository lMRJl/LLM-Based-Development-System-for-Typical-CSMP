# C4 代码风格规范

## 1. 总则

### 1.1 目标
定义管线生成代码的风格标准——缩进、行宽、引号、空行、注释格式、类型注解等，确保代码风格统一、可读、可校验，为 P4（风格一致性衔接）、A5（质量降级中的代码风格项）、Validate Agent（Layer1 ruff校验）提供风格基准。

### 1.2 定位

| 维度 | 说明 |
|------|------|
| **与P4的关系** | P4 §10定义7维风格样本提取，C4定义"命名风格"、"注释风格"、"类型注解"等维度的具体标准 |
| **与A5的关系** | A5 §3 D1质量降级中"代码风格"是可降级项；C4定义代码风格的具体内容 |
| **与C3的关系** | C3定义命名规则；C4定义命名之外的风格要素（缩进、空行、注释等） |
| **与C2的关系** | C2定义代码块输出格式；C4定义代码块内部的具体风格 |
| **与Validate的关系** | A1 §2.8 Layer1使用ruff+ast校验；C4定义ruff的配置基线 |

### 1.3 设计原则

| 原则 | 说明 |
|------|------|
| **工具可执行** | 风格规则尽量可由linter/formatter自动校验和修复，不依赖人工 |
| **语言惯用** | Python遵循PEP8，Vue/JS遵循社区主流规范 |
| **前后端独立** | 后端Python风格和前端Vue/JS风格独立维护（P4 §10.3） |
| **降级友好** | 风格规则分必需/推荐两档，质量降级时可放宽推荐项 |
| **风格样本传播** | 第一个生成文件提取风格样本，通过decision_summary传播给后续文件 |

## 2. Python代码风格

### 2.1 基本格式

| 规则 | 标准 | 说明 |
|------|------|------|
| 缩进 | 4空格 | 禁止Tab |
| 行宽 | 120字符 | ruff `line-length = 120` |
| 引号 | 单引号`'`优先 | 双引号仅用于字符串内含单引号时 |
| 编码 | UTF-8无BOM | Python3默认 |
| 换行符 | LF | 禁止CRLF |
| 尾随空格 | 不允许 | ruff自动移除 |
| 文件末尾换行 | 必须 | 确保文件以换行符结束 |

### 2.2 空行规则

| 场景 | 空行数 | 示例 |
|------|--------|------|
| 模块文档字符串后 | 1 | `"""doc"""\n\nimport ...` |
| 导入组之间 | 1 | 标准库\n\n第三方\n\n本地 |
| 导入后、代码前 | 2 | `import ...\n\n\nCONSTANT = ...` |
| 类定义之间 | 2 | `class A: ...\n\n\nclass B: ...` |
| 类内方法之间 | 1 | `def method1: ...\n\n    def method2: ...` |
| 函数之间 | 2 | 顶层函数之间 |
| 函数内逻辑段之间 | 1 | 按逻辑分段 |

### 2.3 导入风格

导入分组与排序（C5详细定义，此处仅风格层面）：

```python
# 标准库（按字母序）
import json
import os
from datetime import datetime

# 第三方库（按字母序）
from flask import Blueprint, request
from sqlalchemy import desc, or_

# 本地模块（按路径字母序）
from app.models.user import User
from app.api.user_interface import IUserManager
from app.utils.exceptions import ServiceException
```

**风格规则**：

| 规则 | 说明 |
|------|------|
| `import`在前，`from...import`在后 | 同组内先写`import x`，再写`from x import y` |
| 按字母排序 | 同组内按模块名字母序 |
| 禁止通配符导入 | 不允许`from module import *` |
| 禁止相对导入 | 使用`from app.xxx`而非`from .xxx`（C5详细规定） |

### 2.4 类型注解风格

**要求**：所有公开函数必须有完整的类型注解（参数+返回值）。

```python
# ✅ 完整类型注解
def list_users(self, page: int = 1, size: int = 20) -> dict:
    """获取用户列表。"""
    ...

# ✅ 复杂类型使用typing
from typing import Optional, List, Dict

def get_user(self, user_id: int) -> Optional[dict]:
    """获取单个用户。"""
    ...

# ✅ 类方法注解
class UserManager(IUserManager):
    def create_user(self, data: dict) -> dict:
        ...
```

**类型注解规则**：

| 规则 | 说明 |
|------|------|
| 参数必须注解 | 所有函数参数（含self/cls） |
| 返回值必须注解 | `-> dict`, `-> Optional[User]`, `-> None` |
| 私有方法可简化 | `_`前缀方法允许省略返回值注解 |
| 使用内置类型 | Python3.9+用`dict`/`list`/`tuple`，不用`Dict`/`List`/`Tuple` |
| Optional显式 | `Optional[str]`而非`str | None`（兼容性） |

### 2.5 注释风格

#### 模块文档字符串

```python
"""用户管理服务模块。

提供用户CRUD操作的Service层实现。
"""
```

- 一行概述 + 空行 + 详细说明
- Google风格

#### 类文档字符串

```python
class UserManager(IUserManager):
    """用户管理服务。

    继承IUserManager接口，实现用户CRUD业务逻辑。
    """
```

#### 方法文档字符串

```python
def list_users(self, page: int = 1, size: int = 20) -> dict:
    """获取用户列表。

    Args:
        page: 页码，从1开始。
        size: 每页数量，默认20。

    Returns:
        分页结果字典，格式：{"items": [...], "total": int, "page": int, "size": int}

    Raises:
        ServiceException: 当分页参数无效时。
    """
```

**文档字符串规则**：

| 规则 | 说明 |
|------|------|
| 格式 | Google风格 |
| 必须项 | 所有公开类和方法 |
| 可省略 | `__init__`（类文档已描述）、私有方法、简单getter/setter |
| 三引号 | 双引号`"""` |
| Args | 每个参数一行，格式：`参数名: 描述。` |
| Returns | 描述返回值和格式 |
| Raises | 列出可能抛出的异常 |

#### 行内注释

```python
# 计算偏移量（分页公式）
offset = (page - 1) * size
```

- `#`后空一格
- 注释与代码同一逻辑段
- 解释"为什么"而非"做什么"

### 2.6 装饰器风格

```python
@user_bp.route('/', methods=['GET'])
@audit_log(action="list_users")
def list_users():
    ...
```

**规则**：

| 规则 | 说明 |
|------|------|
| 一行一个装饰器 | 禁止同行多装饰器 |
| 顺序 | 路由装饰器→自定义装饰器→内置装饰器 |
| 参数 | 装饰器参数用`=`赋值，不加空格 |

### 2.7 字符串格式化

```python
# ✅ f-string（Python3.6+）
message = f"用户 {username} 创建成功"

# ✅ 多行字符串
query = (
    "SELECT * FROM user "
    "WHERE is_active = 1 "
    "ORDER BY created_at DESC"
)

# ❌ 不使用 % 格式化
# ❌ 不使用 .format()（除非需要延迟格式化）
```


## 3. Vue/JavaScript代码风格

### 3.1 基本格式

| 规则 | 标准 | 说明 |
|------|------|------|
| 缩进 | 2空格 | Vue社区标准 |
| 行宽 | 120字符 | 与Python一致 |
| 引号 | 单引号`'`优先 | ESLint `quotes: ['error', 'single']` |
| 分号 | 不加分号 | ESLint `semi: ['error', 'never']` |
| 尾随逗号 | 多行时添加 | ESLint `comma-dangle: ['error', 'always-multiline']` |
| 换行符 | LF | `.editorconfig` + ESLint |

### 3.2 模板风格

```vue
<template>
  <div class="user-view">
    <el-table :data="userList" v-loading="loading">
      <el-table-column prop="username" label="用户名" />
      <el-table-column prop="role" label="角色" />
      <el-table-column label="操作" width="200">
        <template #default="{ row }">
          <el-button size="small" @click="handleEdit(row)">编辑</el-button>
          <el-button size="small" type="danger" @click="handleDelete(row)">删除</el-button>
        </template>
      </el-table-column>
    </el-table>
  </div>
</template>
```

**模板规则**：

| 规则 | 说明 |
|------|------|
| 组件属性换行 | 多属性时每属性一行 |
| 指令缩写 | 使用`@`代替`v-on:`，`:`代替`v-bind:` |
| 自闭合 | 无内容的组件自闭合`<my-component />` |
| 缩进 | template内2空格 |
| 属性顺序 | `v-for` → `v-if` → `:key` → 其他属性 → `@event` |

### 3.3 Script风格

```javascript
// 组合式函数调用
const userStore = useUserStore()
const router = useRouter()

// 响应式状态
const loading = ref(false)
const userList = ref([])

// 计算属性
const activeUsers = computed(() =>
  userList.value.filter((u) => u.isActive)
)

// 方法
const fetchUsers = async () => {
  loading.value = true
  try {
    const res = await getUserList(pagination)
    userList.value = res.data.items
    pagination.total = res.data.total
  } catch (error) {
    ElMessage.error(error.message || '获取用户列表失败')
  } finally {
    loading.value = false
  }
}

// 生命周期
onMounted(() => {
  fetchUsers()
})
```

**Script规则**：

| 规则 | 说明 |
|------|------|
| `<script setup>` | 必须使用setup语法糖 |
| async/await | 异步操作使用async/await，不用.then() |
| 解构 | Pinia store用`storeToRefs`解构响应式属性 |
| 箭头函数 | 回调和简单函数用箭头函数 |
| 模板引用 | `const tableRef = ref(null)` |

### 3.4 JSDoc风格

```javascript
/**
 * 获取用户列表。
 * @param {Object} params - 查询参数
 * @param {number} params.page - 页码
 * @param {number} params.size - 每页数量
 * @returns {Promise<Object>} 分页结果
 */
export function getUserList(params) {
  return request({ url: '/api/v1/users', method: 'get', params })
}
```

**JSDoc规则**：

| 规则 | 说明 |
|------|------|
| 必须项 | 所有导出函数 |
| 格式 | JSDoc标准 |
| @param | 每个参数一行 |
| @returns | 描述返回值类型 |
| 可省略 | 内部函数、组件内方法 |

## 4. SQL代码风格

### 4.1 格式规则

| 规则 | 标准 | 示例 |
|------|------|------|
| 关键字大写 | `CREATE TABLE`, `SELECT`, `INSERT` | `SELECT id, name FROM user` |
| 表名小写 | snake_case | `operation_log`, `alert_rule` |
| 列名小写 | snake_case | `user_id`, `created_at` |
| 缩进 | 4空格 | 列定义缩进 |
| 逗号位置 | 行首 | 列列表最后一个除外 |
| 列对齐 | 类型、约束对齐 | 按列分组 |

### 4.2 建表格式

```sql
CREATE TABLE IF NOT EXISTS `alert` (
    `id`            INT AUTO_INCREMENT PRIMARY KEY,
    `alert_name`    VARCHAR(200) NOT NULL COMMENT '告警名称',
    `alert_level`   VARCHAR(20)  NOT NULL COMMENT '告警级别: critical/warning/info',
    `alert_status`  VARCHAR(20)  NOT NULL DEFAULT 'pending' COMMENT '告警状态',
    `description`   TEXT         DEFAULT NULL COMMENT '告警描述',
    `source_device` VARCHAR(100) DEFAULT NULL COMMENT '源设备',
    `created_at`    DATETIME     NOT NULL DEFAULT CURRENT_TIMESTAMP,
    `updated_at`    DATETIME     NOT NULL DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP,
    INDEX `idx_alert_level` (`alert_level`),
    INDEX `idx_alert_status` (`alert_status`),
    INDEX `idx_alert_created_at` (`created_at`)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COLLATE=utf8mb4_unicode_ci COMMENT='告警表';
```

## 5. 风格分级与降级

### 5.1 风格分级

| 级别 | 规则 | 降级行为 |
|------|------|---------|
| **必需** | 类型注解、文档字符串（公开方法）、导入分组 | 不可降级 |
| **推荐** | 空行规则、注释密度、行宽限制 | 质量降级时可放宽 |
| **可选** | 行内注释密度、变量命名语义度 | LLM审查时可跳过（A5 §3.4） |

### 5.2 降级行为

对应A5 D1-D3质量降级：

| 降级级别 | 代码风格要求 |
|---------|------------|
| D1-0（正常） | 全部必需+推荐规则 |
| D1-1（轻微降级） | 放宽推荐项：空行规则可简化，注释密度可降低 |
| D1-2（中度降级） | 放宽推荐+简化必需：文档字符串可省略详细描述，类型注解保留参数但可省略返回值 |
| D1-3（重度降级） | 仅保留核心必需：类型注解仅参数，文档字符串仅一行概述 |

## 6. 风格样本提取与传播

### 6.1 提取规则

与P4 §10对齐，第一个生成文件完成后，提取7维风格样本：

| 维度 | 提取内容 | 来源 |
|------|---------|------|
| 命名风格 | snake_case变量/方法，PascalCase类名 | C3 |
| 导入风格 | 三组分组+排序规则 | C5 |
| 异常处理 | ServiceException使用模式 | C6 |
| 装饰器使用 | @audit_log等装饰器模式 | C6 |
| 日志风格 | logger.info/error/warning格式 | C7 |
| 注释风格 | Google风格docstring | C4 §2.5 |
| 类型注解 | 参数+返回值完整注解 | C4 §2.4 |

### 6.2 传播机制

风格样本通过decision_summary传播：

```json
{
  "style_sample": {
    "naming": "snake_case vars/methods, PascalCase classes",
    "imports": "stdlib → third-party → local, sorted alphabetically",
    "docstring": "Google style, Args/Returns/Raises",
    "type_hints": "full (params + return), Optional for nullable",
    "decorators": "@audit_log, @require_role",
    "exception": "ServiceException(code, message)",
    "logger": "logger.info/error with structured message"
  }
}
```

后续文件的Prompt中注入此风格样本（P3 resolve_variables → P1 assemble_prompt），确保风格一致性。

### 6.3 前后端独立

P4 §10.3规定：前后端风格独立维护。

- Backend风格样本：`decision_summary.style_sample`（Python风格）
- Frontend风格样本：`decision_summary.frontend_style_sample`（Vue/JS风格）
- 两者互不影响

## 7. 风格校验规则

### 7.1 Layer1静态分析校验

| 校验项 | 工具 | 规则来源 |
|--------|------|---------|
| Python格式 | ruff format | C4 §2.1-2.8 |
| Python命名 | ruff lint (N规则) | C3 §2 |
| Python导入 | ruff lint (I规则) | C5 |
| Vue/JS格式 | ESLint + Prettier | C4 §3.1-3.6 |
| Vue模板 | eslint-plugin-vue | C4 §3.2 |

### 7.2 Layer2 LLM审查校验

| 校验项 | 规则 | 说明 |
|--------|------|------|
| 文档字符串完整性 | 公开方法必须有Google风格docstring | C4 §2.5 |
| 类型注解完整性 | 公开方法参数+返回值均有注解 | C4 §2.4 |
| 注释质量 | 注释解释"为什么"而非"做什么" | C4 §2.5 |
| 风格一致性 | 与风格样本一致 | C4 §6 |

## 8. 与其他规范的联动

### 8.1 与P4的联动

| C4定义 | P4消费方式 |
|--------|----------|
| 风格样本7维度 | P4 §10风格一致性衔接基于C4的7个维度提取样本 |
| 前后端独立风格 | P4 §10.3前端和后端风格独立维护 |
| 降级行为 | P4衔接约束在A5质量降级时放宽推荐项 |

### 8.2 与A5的联动

| C4定义 | A5消费方式 |
|--------|----------|
| 风格分级 | A5 D1质量降级时按C4分级放宽代码风格要求 |
| 降级行为 | A5 §3.4 LLM审查跳过"代码风格"非核心检查项 |

### 8.3 与Validate的联动

| C4定义 | Validate消费方式 |
|--------|-----------------|
| Ruff配置 | Layer1静态分析使用C4定义的ruff配置基线 |
| ESLint配置 | Layer1前端格式校验使用C4定义的ESLint配置基线 |
| 类型注解 | Layer2检查类型注解完整性 |
