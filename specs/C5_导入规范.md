# C5 导入规范

## 1. 总则

### 1.1 目标
定义管线生成代码中导入语句的规范——分组、排序、路径、去重、禁止项，确保导入声明正确、一致、可校验，为 P4（导入衔接约束）、C4（导入风格）、Validate Agent（Layer1 ruff isort校验）提供导入规则基础。

### 1.2 定位

| 维度 | 说明 |
|------|------|
| **与C1的关系** | C1定义目录结构；C5导入路径必须基于C1目录层级 |
| **与C3的关系** | C3定义命名规则；C5导入的模块名、函数名、类名必须符合C3 |
| **与C4的关系** | C4 §2.3定义导入风格（空行、引号）；C5定义导入的内容规则（分组、路径、去重） |
| **与P4的关系** | P4 §3.2定义跨文件导入衔接约束（`task_handoff_imports`变量）；C5定义导入声明本身的正确性规则 |
| **与A3的关系** | A3定义`RUNTIME_IMPORT_ERROR`错误码；C5定义避免运行时导入错误的编码规则 |

### 1.3 设计原则

| 原则 | 说明 |
|------|------|
| **三组分组** | 标准库→第三方→本地，每组空行分隔，PEP8惯例 |
| **绝对导入优先** | 使用`from app.xxx import`而非`from .xxx import`，路径确定性更强 |
| **显式优于隐式** | 明确导入需要的符号，禁止通配符导入 |
| **去重不重导入** | 不重复导入已在依赖文件中定义的类（P1 TAIL段约束） |
| **路径与C1对齐** | 导入路径精确映射C1目录结构，不可出现不存在的路径 |

## 2. Python导入规范

### 2.1 分组与排序

```python
# ===== 第一组：标准库 =====
import json
import os
from datetime import datetime
from typing import Optional

# ===== 第二组：第三方库 =====
from flask import Blueprint, request, jsonify
from flask_socketio import emit
from sqlalchemy import desc, or_
from sqlalchemy.orm import joinedload

# ===== 第三组：本地模块 =====
from app.models.user import User, Role
from app.api.user_interface import IUserManager
from app.services.base import BaseService
from app.utils.exceptions import ServiceException
from app.utils.pagination import BaseQueryParser
from app.utils.audit import audit_log
```

**排序规则**：

| 规则 | 说明 |
|------|------|
| 组间空行 | 1个空行 |
| 组内排序 | `import x`在前，`from x import y`在后，各自按模块名字母序 |
| 行内排序 | `from x import a, b, c`按字母序 |
| 注释分隔 | 可选，不强制添加`# 标准库`等组注释 |

### 2.2 绝对导入 vs 相对导入

**规则：全部使用绝对导入，禁止相对导入。**

```python
# ✅ 绝对导入
from app.models.user import User
from app.api.user_interface import IUserManager
from app.utils.exceptions import ServiceException

# ❌ 相对导入
from .models.user import User
from ..api.user_interface import IUserManager
from ...utils.exceptions import ServiceException
```

**理由**：
- 绝对导入路径明确，不依赖当前模块位置
- 代码移动后无需修改导入路径
- 与C1目录结构直接对应，便于校验

### 2.3 各层导入规则

按ABC架构分层，定义各层允许导入的范围：

| 层级 | 允许导入 | 禁止导入 | 说明 |
|------|---------|---------|------|
| **Router** (`app/api/*.py`) | Service接口+实现, Model, Utils, Flask | 其他Router | 路由层调用Service，不横向依赖 |
| **Interface** (`app/api/*_interface.py`) | abc, typing, Model(仅类型) | Service, Utils, Flask | ABC定义仅声明方法签名 |
| **Service** (`app/services/*.py`) | Interface, Model, Utils, Device | Router | 业务逻辑层不依赖路由 |
| **Model** (`app/models/*.py`) | extensions(db), base | Service, Router, Utils | 数据层最小依赖 |
| **Device** (`app/device/*.py`) | base, Service(仅接口), Model | Router, Utils | 设备扩展层仅覆盖Service方法 |
| **Utils** (`app/utils/*.py`) | 标准库+第三方 | Model, Service, Router | 工具层零业务依赖 |
| **WebSocket** (`app/websocket/*.py`) | Service, Model, Utils | Router | 事件处理调用Service |

**导入方向图**：

```
Router → Service → Interface
  │         │
  │         ├→ Model
  │         ├→ Device
  │         └→ Utils
  │
  └→ Utils

禁止反向导入：Model ← Service ✗, Utils ← Router ✗
```

### 2.5 导入去重规则

**规则：不重复导入已在依赖文件中定义的类。**

这是P1 TAIL段的核心约束之一：

```
当前文件：app/api/user.py（路由）
依赖文件：app/services/user.py（已导入User, Role, ServiceException）
→ 路由文件不需要再导入User, Role（通过Service方法间接使用）
→ 路由文件需要导入ServiceException（因为直接使用）
```

**去重判断规则**：

| 场景 | 是否需要导入 | 说明 |
|------|------------|------|
| 直接使用类名（如`User(...)`） | 需要导入 | 直接实例化或继承 |
| 仅作为类型注解（如`user: User`） | 需要导入 | 类型注解需要运行时访问 |
| 通过Service方法间接使用 | 不需要导入 | Service内部已导入 |
| 作为函数参数传入 | 需要导入 | 需要知道参数类型 |

### 2.6 条件导入

仅在处理可选依赖时使用条件导入：

```python
# ✅ 可选依赖
try:
    import redis
    REDIS_AVAILABLE = True
except ImportError:
    REDIS_AVAILABLE = False

# ❌ 禁止用于兼容性hack
try:
    from flask import new_api  # 不要这样
except ImportError:
    from flask import old_api
```

### 2.7 禁止项

| 禁止项 | 说明 | 替代方案 |
|--------|------|---------|
| `from module import *` | 污染命名空间，无法静态分析 | 显式列出导入符号 |
| 相对导入 `from .xxx` | 路径不确定，移动后需修改 | 绝对导入 `from app.xxx` |
| 循环导入 | A导入B，B导入A | 重构为三方模块或延迟导入 |
| 导入整个模块再访问 | `import app.models; app.models.User` | `from app.models.user import User` |
| 运行时动态导入 | `__import__('xxx')`或`importlib` | 顶层静态导入 |

## 3. Vue/JavaScript导入规范

### 3.1 分组与排序

```javascript
// ===== 第一组：Vue核心 =====
import { ref, reactive, computed, onMounted, onUnmounted } from 'vue'
import { useRouter, useRoute } from 'vue-router'

// ===== 第二组：第三方库 =====
import { ElMessage, ElMessageBox } from 'element-plus'
import * as echarts from 'echarts'
import { io } from 'socket.io-client'

// ===== 第三组：本地模块 =====
import { getUserList, createUser } from '@/api/user'
import { useUserStore } from '@/stores/user'
import { useAuth } from '@/composables/useAuth'
import StatusTag from '@/components/business/StatusTag.vue'
import UserFormDialog from './UserFormDialog.vue'
```

**排序规则**：

| 规则 | 说明 |
|------|------|
| 组间空行 | 1个空行 |
| 组内排序 | 按模块名字母序 |
| Vue核心优先 | `vue` → `vue-router` → `pinia` |
| 第三方次之 | Element Plus → ECharts → Socket.IO |
| 本地最后 | API → Store → Composable → 组件 |
| 同目录组件 | 使用相对路径`./` |
| 跨目录模块 | 使用别名路径`@/` |

### 3.2 路径别名

| 别名 | 映射 | 说明 |
|------|------|------|
| `@` | `src/` | Vite默认别名 |
| `@/api/` | `src/api/` | API调用模块 |
| `@/stores/` | `src/stores/` | Pinia Store |
| `@/composables/` | `src/composables/` | 组合式函数 |
| `@/components/` | `src/components/` | 公共组件 |
| `@/views/` | `src/views/` | 页面视图 |
| `@/utils/` | `src/utils/` | 工具函数 |

**规则**：

- 跨目录引用使用`@/`别名路径
- 同目录内引用使用`./`相对路径
- 禁止`../`多级相对路径（使用`@/`替代）

```javascript
// ✅ 使用别名
import { getUserList } from '@/api/user'
import StatusTag from '@/components/business/StatusTag.vue'

// ✅ 同目录相对路径
import UserFormDialog from './UserFormDialog.vue'

// ❌ 多级相对路径
import { getUserList } from '../../api/user'
```

### 3.3 各层导入规则

| 层级 | 允许导入 | 禁止导入 | 说明 |
|------|---------|---------|------|
| **API** (`src/api/*.js`) | axios实例, api_def路径 | Store, Component, Composable | API层仅定义调用，不含状态 |
| **Store** (`src/stores/*.js`) | API, Pinia, Vue核心 | Component | Store调用API，不引用组件 |
| **Composable** (`src/composables/*.js`) | API, Store, Vue核心 | 页面级Component | Composable可复用，不绑定页面 |
| **View** (`src/views/**/*.vue`) | API, Store, Composable, 公共Component | 其他View | 页面间不直接引用 |
| **Component** (`src/components/**/*.vue`) | API, Store, Composable, 子Component | View | 公共组件不引用页面 |

### 3.4 ES Module规范

| 规则 | 说明 | 示例 |
|------|------|------|
| 命名导出优先 | API/Store/Composable使用命名导出 | `export function getUserList()` |
| 组件默认导出 | Vue SFC隐式默认导出 | `<script setup>`自动处理 |
| 禁止`export default` | JS模块禁止默认导出 | ✅ `export function` ❌ `export default function` |
| 禁止`require()` | 使用ES Module `import` | — |

### 3.5 禁止项

| 禁止项 | 说明 | 替代方案 |
|--------|------|---------|
| `import * as Module` | 无法tree-shaking | 显式列出导入符号 |
| 多级相对路径 `../../` | 可读性差 | 使用`@/`别名 |
| Vue2 Options API导入 | 项目使用Vue3 Composition API | `import { ref } from 'vue'` |
| 运行时动态导入 | `import()`仅在路由懒加载时使用 | 顶层静态导入 |
| 循环依赖 | Store导入API，API导入Store | API层不导入Store |

## 4. 导入校验规则

### 4.1 Layer1静态分析校验

| 校验项 | 工具 | 规则 |
|--------|------|------|
| Python导入排序 | ruff isort (I规则) | 三组分组+组内字母序 |
| Python未使用导入 | ruff F401 | 移除未使用的导入 |
| Python通配符导入 | ruff F403 | 禁止`import *` |
| Python相对导入 | 自定义ast检查 | 禁止`from .`导入 |
| Vue/JS导入排序 | ESLint import-order | 三组分组+组内字母序 |
| Vue/JS未使用导入 | ESLint no-unused-vars | 移除未使用的导入 |
| Vue/JS路径别名 | ESLint no-relative-imports | 禁止多级`../` |

### 4.2 Layer2 LLM审查校验

| 校验项 | 规则 | 说明 |
|--------|------|------|
| 导入方向 | 遵循2.3/3.3层级规则 | 禁止反向导入 |
| 循环导入 | 无循环依赖 | A→B→A为循环 |
| 去重正确性 | 不重复导入依赖文件中已导入的类 | P1 TAIL约束 |
| 导入路径存在 | 所有导入路径对应C1中存在的文件 | 避免运行时导入错误 |

### 4.3 运行时导入错误

A3定义`RUNTIME_IMPORT_ERROR`错误码（L2级别），C5的导入规范旨在预防此类错误：

| 预防规则 | 避免的运行时错误 |
|---------|-----------------|
| 绝对导入 | `ModuleNotFoundError: No module named '.'` |
| 路径与C1对齐 | `ModuleNotFoundError: No module named 'app.xxx'` |
| 去重不重导入 | `ImportError: cannot import name 'X'` |
| 无循环导入 | `ImportError: circular import` |

## 5. 导入与P4衔接的关系

### 5.1 P4导入衔接约束

P4 §3.2定义跨文件生成时的导入衔接约束，通过`task_handoff_imports`变量注入：

```json
{
  "task_handoff_imports": [
    "from app.models.user import User",
    "from app.api.user_interface import IUserManager",
    "from app.utils.exceptions import ServiceException"
  ]
}
```

C5定义这些导入语句的正确性规则：
- 路径必须基于C1目录
- 符号命名必须符合C3
- 分组排序必须符合C5

### 5.2 衔接注入流程

```
前序文件生成完成 → 提取签名和导入 → 构建task_handoff_imports
    → P3 resolve_variables注入当前Prompt → TAIL段输出约束
    → LLM生成代码时使用这些导入 → C5校验导入正确性
```

### 6.1 与C1的联动

| C5定义 | C1消费方式 |
|--------|----------|
| 导入路径 | 必须映射到C1目录结构中存在的文件 |
| 层级导入规则 | 基于C1的ABC架构分层定义 |

### 6.2 与C4的联动

| C5定义 | C4消费方式 |
|--------|----------|
| 分组规则 | C4 §2.3导入风格基于C5分组规则 |
| 排序规则 | C4 ruff isort配置基于C5排序规则 |

### 6.3 与P4的联动

| C5定义 | P4消费方式 |
|--------|----------|
| 导入正确性规则 | P4衔接约束中的导入声明必须符合C5 |
| task_handoff_imports | P4 §3.2衔接变量的内容必须符合C5路径和命名规则 |
