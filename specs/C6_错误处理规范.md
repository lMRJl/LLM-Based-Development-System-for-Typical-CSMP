# C6 错误处理规范

## 1. 总则

### 1.1 目标
定义管线生成代码中的错误处理标准——异常类层次、处理模式、错误响应格式、日志记录、安全约束，确保错误处理统一、安全、可追溯，为 P5（安全错误处理）、D4（错误数据规范）、C7（错误日志规范）提供代码级错误处理基础。

### 1.2 定位

| 维度 | 说明 |
|------|------|
| **与A1的关系** | A1决策摘要定义`ServiceException(code, message)`异常类；C6定义该类的完整层次和使用模式 |
| **与P5的关系** | P5 §7定义生成代码安全约束（不暴露堆栈跟踪、不泄露内部实现）；C6定义错误处理的安全实现 |
| **与D4的关系** | D4定义管线错误数据的完整生命周期；C6定义代码级异常如何映射到D4错误记录 |
| **与C7的关系** | C7定义日志规范；C6定义错误处理中日志记录的具体内容和格式 |
| **与P4的关系** | P4 §10风格样本"异常处理"维度规则来源为C6 |

### 1.3 设计原则

| 原则 | 说明 |
|------|------|
| **统一异常类** | 所有业务异常统一使用`ServiceException`，不散落各处自定义 |
| **分层处理** | 路由层捕获→Service层抛出→Model层包装，各层职责清晰 |
| **安全优先** | 错误响应不暴露内部实现、堆栈跟踪、敏感数据（P5 §7.1） |
| **日志必记** | 每次异常发生必须记录结构化日志，不静默吞没 |
| **错误码可枚举** | 错误码使用常量定义，可枚举、可文档化 |

## 2. Python错误处理

### 2.1 异常类层次

```
Exception
└── ServiceException                    # 基础业务异常
    ├── code: int                       # 业务错误码
    ├── message: str                    # 面向用户的错误消息
    ├── detail: str | None              # 内部详细信息（不返回给用户）
    └── __init__(self, code, message, detail=None)
```

**异常类定义**：

```python
"""统一异常类定义。"""

from typing import Optional


class ServiceException(Exception):
    """业务异常基类。

    所有业务逻辑错误统一使用此异常类，由全局错误处理器捕获并返回标准响应。

    Args:
        code: 业务错误码（HTTP状态码语义）。
        message: 面向用户的错误消息。
        detail: 内部详细信息，仅记录日志，不返回给用户。
    """

    def __init__(self, code: int = 400, message: str = '操作失败', detail: Optional[str] = None):
        self.code = code
        self.message = message
        self.detail = detail
        super().__init__(self.message)


class ValidationError(ServiceException):
    """参数校验异常。"""

    def __init__(self, message: str = '参数校验失败', detail: Optional[str] = None):
        super().__init__(code=422, message=message, detail=detail)


class NotFoundError(ServiceException):
    """资源不存在异常。"""

    def __init__(self, message: str = '资源不存在', detail: Optional[str] = None):
        super().__init__(code=404, message=message, detail=detail)


class AuthError(ServiceException):
    """认证/授权异常。"""

    def __init__(self, message: str = '认证失败', detail: Optional[str] = None):
        super().__init__(code=401, message=message, detail=detail)


class ForbiddenError(ServiceException):
    """权限不足异常。"""

    def __init__(self, message: str = '权限不足', detail: Optional[str] = None):
        super().__init__(code=403, message=message, detail=detail)
```

### 2.2 错误码定义

| 错误码 | HTTP语义 | 使用场景 |
|--------|---------|---------|
| 400 | Bad Request | 请求参数格式错误 |
| 401 | Unauthorized | 未认证或Token过期 |
| 403 | Forbidden | 权限不足 |
| 404 | Not Found | 资源不存在 |
| 409 | Conflict | 资源冲突（如重复创建） |
| 422 | Unprocessable Entity | 业务校验失败 |
| 429 | Too Many Requests | 请求频率超限 |
| 500 | Internal Server Error | 服务器内部错误（仅由全局处理器返回） |

### 2.3 各层错误处理模式

#### 路由层（Router）

路由层负责捕获异常并返回标准响应，**不包含业务逻辑**：

```python
@user_bp.route('/', methods=['GET'])
@audit_log(action="list_users")
def list_users():
    """用户列表接口。"""
    try:
        parser = BaseQueryParser()
        params = parser.parse(request.args)
        manager = UserManager()
        result = manager.list_users(**params)
        return jsonify(code=200, data=result, message='success')
    except ServiceException as e:
        logger.warning(f"业务异常: {e.message}", extra={'detail': e.detail})
        return jsonify(code=e.code, data=None, message=e.message), e.code
    except Exception as e:
        logger.error(f"未预期异常: {str(e)}", exc_info=True)
        return jsonify(code=500, data=None, message='服务器内部错误'), 500
```

**路由层规则**：

| 规则 | 说明 |
|------|------|
| 必须try/except | 每个路由函数必须有异常捕获 |
| ServiceException → 业务响应 | 返回code+message，不暴露detail |
| Exception → 500 | 未预期异常返回通用500消息 |
| 不抛出异常 | 路由层不再向上抛出，是异常处理的终点 |
| 日志记录 | 每次异常必须记录日志 |

#### Service层

Service层负责业务逻辑校验，**主动抛出ServiceException**：

```python
class UserManager(IUserManager):
    def create_user(self, data: dict) -> dict:
        """创建用户。"""
        # 业务校验
        existing = User.query.filter_by(username=data.get('username')).first()
        if existing:
            raise ServiceException(
                code=409,
                message='用户名已存在',
                detail=f"Duplicate username: {data.get('username')}"
            )

        # 创建用户
        try:
            user = User(**data)
            db.session.add(user)
            db.session.commit()
        except Exception as e:
            db.session.rollback()
            raise ServiceException(
                code=500,
                message='创建用户失败',
                detail=str(e)
            )

        return user.to_dict()
```

**Service层规则**：

| 规则 | 说明 |
|------|------|
| 主动抛出 | 检测到业务错误时主动raise ServiceException |
| detail可选 | 内部详细信息放detail，不放message |
| 数据库回滚 | DB操作失败必须rollback |
| 不捕获未知异常 | 除DB操作外，不捕获非ServiceException |

#### Model层

Model层仅定义数据结构，**不包含错误处理逻辑**：

```python
class User(db.Model, BaseModel):
    """用户模型。"""

    __tablename__ = 'user'

    username = db.Column(db.String(50), nullable=False, unique=True, comment='用户名')
    ...
```

**Model层规则**：

| 规则 | 说明 |
|------|------|
| 不抛出业务异常 | Model层不包含业务逻辑 |
| IntegrityError包装 | SQLAlchemy唯一约束冲突由Service层捕获并包装为ServiceException |
| to_dict方法 | 提供序列化方法，不包含错误处理 |

### 2.4 全局错误处理器

Flask全局错误处理器作为最后防线：

```python
"""全局错误处理器。"""

from flask import jsonify
from app.utils.exceptions import ServiceException
import logging

logger = logging.getLogger(__name__)


def register_error_handlers(app):
    """注册全局错误处理器。"""

    @app.errorhandler(ServiceException)
    def handle_service_exception(e):
        """处理业务异常。"""
        logger.warning(f"ServiceException: code={e.code}, message={e.message}")
        response = jsonify(code=e.code, data=None, message=e.message)
        response.status_code = e.code
        return response

    @app.errorhandler(404)
    def handle_not_found(e):
        """处理404。"""
        return jsonify(code=404, data=None, message='资源不存在'), 404

    @app.errorhandler(500)
    def handle_internal_error(e):
        """处理500。"""
        logger.error(f"Internal error: {str(e)}", exc_info=True)
        return jsonify(code=500, data=None, message='服务器内部错误'), 500

    @app.errorhandler(Exception)
    def handle_generic_exception(e):
        """处理所有未捕获异常。"""
        logger.error(f"Unhandled exception: {str(e)}", exc_info=True)
        return jsonify(code=500, data=None, message='服务器内部错误'), 500
```

### 2.6 WebSocket错误处理

```python
@socketio.on('connect', namespace='/ws/monitor')
def handle_connect():
    """处理WebSocket连接。"""
    try:
        # 认证检查
        token = request.args.get('token')
        if not verify_token(token):
            emit('error', {'code': 401, 'message': '认证失败'})
            return False  # 拒绝连接
        logger.info(f"WebSocket client connected: {request.sid}")
    except Exception as e:
        logger.error(f"WebSocket connect error: {str(e)}")
        return False


@socketio.on('subscribe_metrics', namespace='/ws/monitor')
def handle_subscribe(data):
    """处理订阅请求。"""
    try:
        # 处理订阅逻辑
        ...
    except ServiceException as e:
        emit('error', {'code': e.code, 'message': e.message})
    except Exception as e:
        logger.error(f"Subscribe error: {str(e)}")
        emit('error', {'code': 500, 'message': '服务器内部错误'})
```

**WebSocket错误处理规则**：

| 规则 | 说明 |
|------|------|
| emit错误事件 | 使用`emit('error', {...})`通知客户端 |
| 连接拒绝 | 返回`False`拒绝连接 |
| 不抛出异常 | WebSocket处理器内不抛出，直接emit |

## 3. Vue/JavaScript错误处理

### 3.1 API调用错误处理

```javascript
const fetchUsers = async () => {
  loading.value = true
  try {
    const res = await getUserList(pagination)
    userList.value = res.data.items
    pagination.total = res.data.total
  } catch (error) {
    // axios拦截器已处理通用错误，此处仅处理业务特定错误
    if (error.response?.status === 404) {
      ElMessage.warning('用户数据不存在')
    } else {
      ElMessage.error(error.response?.data?.message || '获取用户列表失败')
    }
  } finally {
    loading.value = false
  }
}
```

### 3.2 全局Axios拦截器

```javascript
import axios from 'axios'
import { ElMessage } from 'element-plus'
import { useUserStore } from '@/stores/user'

const request = axios.create({
  baseURL: import.meta.env.VITE_API_BASE_URL,
  timeout: 30000,
})

// 请求拦截器
request.interceptors.request.use(
  (config) => {
    const userStore = useUserStore()
    if (userStore.token) {
      config.headers.Authorization = `Bearer ${userStore.token}`
    }
    return config
  },
  (error) => Promise.reject(error)
)

// 响应拦截器
request.interceptors.response.use(
  (response) => {
    const { code, data, message } = response.data
    if (code === 200) {
      return response.data
    }
    // 业务错误
    ElMessage.error(message || '操作失败')
    return Promise.reject(new Error(message))
  },
  (error) => {
    // HTTP错误
    if (error.response?.status === 401) {
      const userStore = useUserStore()
      userStore.logout()
      window.location.href = '/login'
    } else if (error.response?.status === 403) {
      ElMessage.error('权限不足')
    } else if (error.response?.status >= 500) {
      ElMessage.error('服务器错误，请稍后重试')
    } else {
      ElMessage.error(error.response?.data?.message || '请求失败')
    }
    return Promise.reject(error)
  }
)

export default request
```

### 3.5 前端错误处理规则

| 规则 | 说明 |
|------|------|
| try/catch | 所有async函数调用必须try/catch |

## 4. 安全约束

### 4.1 错误信息安全规则

与P5 §7.1对齐：

| 规则 | 说明 | 示例 |
|------|------|------|
| 不暴露堆栈跟踪 | 错误响应不含`traceback` | ✅ `"message": "操作失败"` ❌ `"traceback": "File ..."` |
| 不暴露内部实现 | 错误消息不含SQL/路径/类名 | ✅ `"用户不存在"` ❌ `"User.query.filter_by returned None"` |
| 不暴露敏感数据 | 错误消息不含密码/Token | ✅ `"认证失败"` ❌ `"Token xxx is expired"` |
| detail不返回前端 | `detail`字段仅记录日志 | 详见2.3路由层规则 |
| 通用500消息 | 服务器错误统一返回"服务器内部错误" | 不区分具体错误类型 |

### 4.2 错误日志安全规则

| 规则 | 说明 |
|------|------|
| 日志不含密码 | 不记录请求中的密码字段 |
| 日志不含Token | 不记录完整的JWT Token |
| 日志不含个人隐私 | 不记录身份证号、手机号等 |
| 错误ID替代 | 使用error_id引用错误，不传递完整错误对象 |

## 5. 错误处理与D4错误数据的映射

### 5.1 代码异常到D4错误记录

代码中的异常如何映射到D4定义的错误数据体系：

| 代码层 | D4映射 | 说明 |
|--------|--------|------|
| `raise ServiceException(code=409)` | D4 ErrorRecord，source_layer=LOGIC | 业务逻辑错误 |
| `db.session.rollback()` | D4 ErrorRecord，source_layer=DATA | 数据库操作错误 |
| `ServiceException(detail=str(e))` | D4 enrichments.llm_context | 内部详情记录到enrichments |
| `logger.error(msg, exc_info=True)` | D4 lifecycle: detected→propagated | 日志触发错误记录 |

### 5.2 错误码映射

| C6错误码 | D4错误码 | 说明 |
|---------|---------|------|
| 400 | INPUT_BUSINESS_INVALID | 请求参数业务校验失败 |
| 401 | —（由认证中间件处理） | 不进D4管线错误 |
| 422 | INPUT_SCHEMA_VIOLATION | 请求参数格式错误 |
| 409 | INPUT_BUSINESS_INVALID | 资源冲突 |
| 500 | OUTPUT_BUSINESS_INCOMPLETE | 生成产物不完整 |

## 6. 装饰器与错误处理

### 6.1 @audit_log与错误处理

`@audit_log`装饰器记录操作审计日志，与错误处理的关系：

```python
@user_bp.route('/', methods=['POST'])
@audit_log(action="create_user")
def create_user():
    try:
        ...
    except ServiceException as e:
        # audit_log已记录操作开始，此处记录操作失败
        logger.warning(f"操作失败: action=create_user, error={e.message}")
        return jsonify(code=e.code, data=None, message=e.message), e.code
```

**规则**：

| 规则 | 说明 |
|------|------|
| audit_log不捕获异常 | 审计装饰器不改变异常传播路径 |
| 失败也审计 | 审计日志记录操作结果（成功/失败） |
| 异常码记录 | 审计日志包含错误码 |

## 7. 错误处理校验规则

### 7.1 Layer1静态分析校验

| 校验项 | 工具 | 规则 |
|--------|------|------|
| 路由函数try/except | 自定义ast检查 | 每个路由函数必须有try/except |
| 异常类使用 | ruff (B规则) | 禁止裸`except:`，必须指定异常类型 |
| ServiceException使用 | 自定义检查 | 业务异常必须使用ServiceException而非通用Exception |

### 7.2 Layer2 LLM审查校验

| 校验项 | 规则 | 说明 |
|--------|------|------|
| 错误响应格式 | 符合`{code, data, message}` | 与A1决策摘要一致 |
| 安全约束 | 不暴露内部信息 | P5 §7.1安全规则 |
| 日志记录 | 每次异常有日志 | C7日志规范 |
| DB回滚 | 数据库操作失败有rollback | 数据一致性 |

### 7.3 Layer2.5契约校验

| 校验项 | 规则 | 说明 |
|--------|------|------|
| 前后端错误码一致 | 前端处理的HTTP状态码与后端返回一致 | api_def.json定义 |
| 前端错误消息 | 前端错误提示与api_def.json错误响应定义一致 | 契约驱动 |

## 8. 与其他规范的联动

### 8.1 与P5的联动

| C6定义 | P5消费方式 |
|--------|----------|
| 安全错误处理 | P5 §7.1安全禁止项"不要在错误响应中暴露堆栈跟踪"基于C6实现 |
| 错误信息安全 | P5 §7.1安全审查清单"错误响应不含堆栈跟踪"校验C6规则 |

### 8.2 与D4的联动

| C6定义 | D4消费方式 |
|--------|----------|
| ServiceException | D4 ErrorRecord的source_layer=LOGIC类错误来源 |
| 错误码 | C6错误码映射到D4扩展错误码 |
| detail字段 | D4 enrichments.llm_context存储C6的detail信息 |

### 8.3 与C7的联动

| C6定义 | C7消费方式 |
|--------|----------|
| 异常日志 | C7定义`logger.error/warning`的格式，C6定义记录什么内容 |
| exc_info=True | C7定义异常日志是否包含堆栈信息 |
