# C7 日志规范

## 1. 总则

### 1.1 目标
定义管线生成代码中的日志标准——日志级别、消息格式、结构化字段、审计日志、敏感数据脱敏、日志文件组织，确保日志统一、安全、可检索，为 A5（容错可观测）、A2（调度日志）、D3（传递日志）、C6（异常日志）提供日志规范基础。

### 1.2 定位

| 维度 | 说明 |
|------|------|
| **与A5的关系** | A5 §10定义错误传播与隔离中的日志隔离；C7定义日志内容的具体格式和脱敏规则 |
| **与A2的关系** | A2 §7定义调度日志格式；C7定义应用代码级的日志格式，与调度日志互补 |
| **与A3的关系** | A3 §4.1定义日志目录结构（`logs/pipeline.log`等）；C7定义代码内日志的输出目标 |
| **与D3的关系** | D3 §6定义transfer.log传递日志；C7定义应用日志，与传递日志不同职责 |
| **与C6的关系** | C6定义异常日志记录什么内容；C7定义日志输出的格式和规则 |
| **与P4的关系** | P4 §10风格样本"日志风格"维度规则来源为C7 |

### 1.3 设计原则

| 原则 | 说明 |
|------|------|
| **结构化优先** | 日志消息包含结构化字段（key=value），便于机器解析和检索 |
| **级别语义明确** | 每个日志级别有确定的语义边界，不滥用 |
| **安全脱敏** | 日志中不出现密码、Token、个人隐私等敏感信息 |
| **审计分离** | 业务审计日志与应用运行日志分离，独立存储和查询 |
| **性能友好** | 日志不阻塞主流程，异步写入或缓冲 |

## 2. Python日志规范

### 2.1 Logger创建

```python
import logging

logger = logging.getLogger(__name__)
```

**规则**：

| 规则 | 说明 |
|------|------|
| 使用`__name__` | Logger名与模块路径对应，如`app.services.user` |
| 模块级创建 | Logger在模块顶部创建，不在函数内 |
| 不创建根Logger | 不使用`logging.getLogger()`（空字符串） |
| 不配置Logger | Logger配置统一在`app/__init__.py`中，模块只获取 |

### 2.2 日志级别语义

| 级别 | 语义 | 使用场景 | 示例 |
|------|------|---------|------|
| `DEBUG` | 详细诊断信息 | 仅开发环境，变量值、SQL语句 | `logger.debug(f"Query params: {params}")` |
| `INFO` | 正常操作里程碑 | 业务操作完成、服务启动 | `logger.info("User created: user_id=123")` |
| `WARNING` | 非预期但可恢复 | 业务校验失败、降级触发 | `logger.warning("Slow query detected: 2.5s")` |
| `ERROR` | 需要关注的错误 | 异常捕获、操作失败 | `logger.error("Failed to create user", exc_info=True)` |
| `CRITICAL` | 系统级故障 | 数据库不可用、服务无法启动 | `logger.critical("Database connection failed")` |

**级别选择规则**：

| 场景 | 级别 | 说明 |
|------|------|------|
| ServiceException捕获 | WARNING | 业务异常是预期内的 |
| 非预期Exception捕获 | ERROR | 未知错误需要关注 |
| DB连接失败 | CRITICAL | 核心依赖不可用 |
| 请求开始/完成 | INFO | 正常操作里程碑 |
| 缓存命中/未命中 | DEBUG | 仅开发调试 |
| 降级触发 | WARNING | 非预期但可恢复 |
| 重试中 | WARNING | 可能需要关注 |

### 2.3 日志消息格式

#### 结构化日志格式

```
{timestamp} | {level} | {module} | {message} | {key1}=val1 | {key2}=val2
```

**示例**：

```
2026-04-30 10:00:00,123 | INFO | app.services.user | User created | user_id=123 | username=admin
2026-04-30 10:00:01,456 | WARNING | app.services.alert | Business exception | code=409 | message=Alert already exists
2026-04-30 10:00:02,789 | ERROR | app.api.monitor | Unhandled exception | error=ConnectionTimeout | exc_info=True
```

#### 日志配置

```python
"""日志配置。"""

import logging
import os


def setup_logging(app):
    """配置应用日志。"""
    log_level = os.environ.get('LOG_LEVEL', 'INFO').upper()
    log_format = '%(asctime)s | %(levelname)s | %(name)s | %(message)s'
    date_format = '%Y-%m-%d %H:%M:%S'

    # 控制台输出
    console_handler = logging.StreamHandler()
    console_handler.setFormatter(logging.Formatter(log_format, date_format))

    # 文件输出
    file_handler = logging.FileHandler('logs/app.log', encoding='utf-8')
    file_handler.setFormatter(logging.Formatter(log_format, date_format))

    # 根Logger配置
    root_logger = logging.getLogger()
    root_logger.setLevel(getattr(logging, log_level, logging.INFO))
    root_logger.addHandler(console_handler)
    root_logger.addHandler(file_handler)

    # 第三方库日志级别
    logging.getLogger('sqlalchemy.engine').setLevel(logging.WARNING)
    logging.getLogger('engineio.server').setLevel(logging.WARNING)
    logging.getLogger('socketio.server').setLevel(logging.WARNING)
```

### 2.4 各层日志记录规则

#### 路由层日志

```python
@user_bp.route('/', methods=['GET'])
@audit_log(action="list_users")
def list_users():
    """用户列表接口。"""
    logger.debug(f"list_users called | params={dict(request.args)}")
    try:
        ...
        logger.info(f"list_users completed | total={result['total']}")
        return jsonify(code=200, data=result, message='success')
    except ServiceException as e:
        logger.warning(f"Business exception | action=list_users | code={e.code} | message={e.message}")
        ...
    except Exception as e:
        logger.error(f"Unhandled exception | action=list_users", exc_info=True)
        ...
```

#### Service层日志

```python
class UserManager(IUserManager):
    def create_user(self, data: dict) -> dict:
        """创建用户。"""
        logger.info(f"Creating user | username={data.get('username')}")
        try:
            user = User(**data)
            db.session.add(user)
            db.session.commit()
            logger.info(f"User created | user_id={user.id} | username={user.username}")
            return user.to_dict()
        except IntegrityError as e:
            db.session.rollback()
            logger.warning(f"User creation failed: duplicate | username={data.get('username')}")
            raise ServiceException(code=409, message='用户名已存在', detail=str(e))
        except Exception as e:
            db.session.rollback()
            logger.error(f"User creation failed | username={data.get('username')}", exc_info=True)
            raise ServiceException(code=500, message='创建用户失败', detail=str(e))
```

**各层日志规则**：

| 层级 | 日志内容 | 级别 |
|------|---------|------|
| Router | 请求进入、业务异常、未预期异常 | DEBUG/INFO/WARNING/ERROR |
| Service | 业务操作开始/完成、业务校验失败 | INFO/WARNING |
| Model | 不记录日志（由Service层统一记录） | — |
| Utils | 工具函数内部错误（如分页参数无效） | WARNING |
| WebSocket | 连接/断开/订阅/错误 | INFO/WARNING/ERROR |

### 2.5 异常日志格式

| 异常类型 | 日志格式 | 级别 |
|---------|---------|------|
| ServiceException | `Business exception \| action={action} \| code={e.code} \| message={e.message}` | WARNING |
| 数据库异常 | `DB operation failed \| operation={op} \| table={table}`, `exc_info=True` | ERROR |
| 未预期异常 | `Unhandled exception \| action={action}`, `exc_info=True` | ERROR |
| 连接异常 | `Connection failed \| service={service} \| error={str(e)}` | CRITICAL |

**`exc_info`使用规则**：

| 场景 | `exc_info` | 说明 |
|------|-----------|------|
| ServiceException | `False`（默认） | 业务异常不需要堆栈，detail字段已记录 |
| 数据库异常 | `True` | 需要完整堆栈辅助定位 |
| 未预期异常 | `True` | 必须记录完整堆栈 |
| 连接异常 | `True` | 需要完整堆栈 |

### 2.6 敏感数据脱敏

**必须脱敏的字段**：

| 字段类型 | 脱敏方式 | 示例 |
|---------|---------|------|
| 密码 | 完全替换 | `password=***` |
| Token | 保留前6位 | `token=eyJhbG...***` |
| 手机号 | 保留前3后4 | `phone=138****5678` |
| 身份证号 | 保留前3后4 | `id_card=110***********1234` |
| API Key | 保留前4位 | `api_key=sk-a***` |

**脱敏工具函数**：

```python
"""敏感数据脱敏工具。"""

SENSITIVE_KEYS = {'password', 'token', 'secret', 'api_key', 'access_token', 'refresh_token'}


def mask_sensitive_data(data: dict) -> dict:
    """脱敏字典中的敏感字段。

    Args:
        data: 原始数据字典。

    Returns:
        脱敏后的字典副本。
    """
    masked = data.copy()
    for key in masked:
        if key.lower() in SENSITIVE_KEYS:
            masked[key] = '***'
    return masked


def mask_token(token: str, visible_prefix: int = 6) -> str:
    """脱敏Token字符串。

    Args:
        token: 原始Token。
        visible_prefix: 保留的前缀字符数。

    Returns:
        脱敏后的Token。
    """
    if len(token) <= visible_prefix:
        return '***'
    return f"{token[:visible_prefix]}***"
```

**使用方式**：

```python
# ✅ 日志中脱敏
logger.info(f"Login attempt | username={username} | password=***")

# ✅ 动态脱敏
params = mask_sensitive_data(request.json or {})
logger.debug(f"Request params | params={params}")

# ❌ 不脱敏
logger.info(f"Login attempt | username={username} | password={password}")
```

## 3. 审计日志

### 3.1 @audit_log装饰器

```python
"""审计日志装饰器。"""

import logging
from functools import wraps
from flask import request, g

audit_logger = logging.getLogger('audit')


def audit_log(action: str):
    """审计日志装饰器。

    记录API操作的时间、操作者、动作和结果。

    Args:
        action: 操作名称。
    """
    def decorator(func):
        @wraps(func)
        def wrapper(*args, **kwargs):
            user_id = getattr(g, 'user_id', 'anonymous')
            client_ip = request.remote_addr
            audit_logger.info(
                f"AUDIT | action={action} | user_id={user_id} | "
                f"ip={client_ip} | method={request.method} | path={request.path}"
            )
            try:
                result = func(*args, **kwargs)
                audit_logger.info(
                    f"AUDIT | action={action} | user_id={user_id} | result=success"
                )
                return result
            except Exception as e:
                audit_logger.warning(
                    f"AUDIT | action={action} | user_id={user_id} | result=failed | error={str(e)}"
                )
                raise
        return wrapper
    return decorator
```

### 3.2 审计日志格式

```
AUDIT | action={操作名} | user_id={用户ID} | ip={客户端IP} | method={HTTP方法} | path={请求路径} | result={成功/失败}
```

**审计日志与应用日志的区别**：

| 维度 | 应用日志 | 审计日志 |
|------|---------|---------|
| 目的 | 诊断和排障 | 合规和追溯 |
| 内容 | 技术细节 | 业务操作 |
| Logger | `logging.getLogger(__name__)` | `logging.getLogger('audit')` |
| 输出 | `logs/app.log` | `logs/audit.log` |
| 保留期限 | 30天 | 1年 |
| 级别 | DEBUG~CRITICAL | INFO+WARNING |

### 3.3 审计日志必须记录的操作

| 操作 | action名 | 说明 |
|------|---------|------|
| 用户登录 | `login` | 记录登录成功/失败 |
| 用户登出 | `logout` | 记录登出 |
| 创建用户 | `create_user` | 记录操作者 |
| 删除用户 | `delete_user` | 记录操作者+被删除用户 |
| 修改角色 | `update_role` | 记录操作者+变更内容 |
| 告警确认 | `acknowledge_alert` | 记录操作者+告警ID |
| 告警处理 | `resolve_alert` | 记录操作者+告警ID |
| 配置变更 | `update_config` | 记录操作者+变更项 |

```
logs/
├── app.log                        # 应用运行日志

└── agent_logs/                    # Agent日志（A5）
    ├── backend_agent.log
    ├── frontend_agent.log
    └── ...
```

### 4.2 日志轮转

```python
"""日志轮转配置。"""

from logging.handlers import RotatingFileHandler


def setup_file_handler(log_file: str, max_bytes: int = 10 * 1024 * 1024, backup_count: int = 5):
    """配置日志文件轮转。

    Args:
        log_file: 日志文件路径。
        max_bytes: 单个文件最大字节数，默认10MB。
        backup_count: 保留的备份文件数，默认5个。

    Returns:
        RotatingFileHandler实例。
    """
    handler = RotatingFileHandler(
        log_file,
        maxBytes=max_bytes,
        backupCount=backup_count,
        encoding='utf-8'
    )
    return handler
```

**轮转配置**：

| 日志文件 | 单文件大小 | 保留份数 | 总最大空间 |
|---------|-----------|---------|-----------|
| app.log | 10MB | 5 | ~60MB |
| audit.log | 10MB | 10 | ~110MB |
| pipeline.log | 10MB | 5 | ~60MB |
| agent_logs/*.log | 5MB | 3 | 每Agent~20MB |

## 5. Vue/JavaScript日志规范

### 5.1 日志工具

```javascript
/**
 * 日志工具模块。
 */

const LOG_LEVELS = {
  DEBUG: 0,
  INFO: 1,
  WARN: 2,
  ERROR: 3,
  SILENT: 4,
}

const currentLevel = import.meta.env.PROD
  ? LOG_LEVELS.WARN
  : LOG_LEVELS.DEBUG

export const logger = {
  debug(...args) {
    if (currentLevel <= LOG_LEVELS.DEBUG) {
      console.debug(`[DEBUG] ${new Date().toISOString()} |`, ...args)
    }
  },

  info(...args) {
    if (currentLevel <= LOG_LEVELS.INFO) {
      console.info(`[INFO] ${new Date().toISOString()} |`, ...args)
    }
  },

  warn(...args) {
    if (currentLevel <= LOG_LEVELS.WARN) {
      console.warn(`[WARN] ${new Date().toISOString()} |`, ...args)
    }
  },

  error(...args) {
    if (currentLevel <= LOG_LEVELS.ERROR) {
      console.error(`[ERROR] ${new Date().toISOString()} |`, ...args)
    }
  },
}
```

### 5.2 前端日志规则

| 规则 | 说明 |
|------|------|
| 生产环境仅WARN+ | `import.meta.env.PROD`为true时仅输出WARN和ERROR |
| 开发环境全级别 | 开发环境输出DEBUG及以上 |
| 不暴露敏感数据 | 前端日志不记录Token、密码 |
| API错误记录 | 请求失败时记录URL和状态码，不记录响应体 |
| 路由切换记录 | INFO级别记录路由切换 |

### 5.3 前端各场景日志

```javascript
// API调用
logger.info(`API request | method=${method} | url=${url}`)
logger.error(`API error | status=${error.response?.status} | url=${url}`)

// 路由切换
logger.info(`Route change | from=${from.path} | to=${to.path}`)

// WebSocket
logger.info(`WebSocket | event=connected | namespace=${namespace}`)
logger.warn(`WebSocket | event=reconnect | attempt=${attempt}`)

// 用户操作
logger.info(`User action | action=${action} | target=${target}`)
```

## 6. 日志与A5容错的关系

### 6.1 日志隔离

A5 §10定义错误日志隔离，C7实现日志隔离的具体规则：

| 隔离维度 | 实现 | 说明 |
|---------|------|------|
| Agent隔离 | 各Agent日志文件独立 | `agent_logs/backend_agent.log` |
| 级别隔离 | 应用日志/审计日志/传递日志分文件 | `app.log`/`audit.log`/`transfer.log` |
| 模块隔离 | Logger名包含模块路径 | `app.services.user` |

### 6.2 容错可观测

A5定义的容错动作产生结构化日志：

| 容错动作 | 日志格式 | 级别 |
|---------|---------|------|
| 重试 | `Retrying | agent={agent} | file={file} | attempt={n}/{max}` | WARNING |
| 降级 | `Degrading | agent={agent} | level={D1} | reason={reason}` | WARNING |
| 断路器开启 | `Circuit breaker OPEN | agent={agent} | module={module}` | ERROR |
| 断路器半开 | `Circuit breaker HALF-OPEN | agent={agent}` | WARNING |
| 回退 | `Rolling back | from={stage} | to={stage} | reason={reason}` | ERROR |
| 部分完成标记 | `Partial completion | agent={agent} | completed={files} | failed={files}` | WARNING |

## 7. 日志校验规则

### 7.1 Layer1静态分析校验

| 校验项 | 工具 | 规则 |
|--------|------|------|
| Logger创建 | 自定义ast检查 | 使用`logging.getLogger(__name__)` |
| 日志级别合理 | 自定义检查 | 无CRITICAL滥用（每个模块最多1处） |
| 敏感数据 | 自定义检查 | 日志中不出现`password=`、`token=`等原始值 |
| print语句 | ruff T201 | 禁止print，使用logger |

### 7.2 Layer2 LLM审查校验

| 校验项 | 规则 | 说明 |
|--------|------|------|
| 异常有日志 | 每个except块有logger调用 | 不静默吞没异常 |
| 日志消息质量 | 包含操作上下文（action/module/id） | 可追溯 |
| 脱敏完整性 | 敏感字段已脱敏 | P5安全规则 |
| 审计日志覆盖 | 关键操作有@audit_log | C7 §3.3清单 |
